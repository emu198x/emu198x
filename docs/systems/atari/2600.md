# Atari 2600 (VCS)

## Status: Boots carts; Combat renders and is playable

Capture + Script + MCP, plus a native window (default mode, via the shared
`emu198x-ui` harness). Combat
boots to its two-tank playfield; the joystick is validated against MAME. 6507
(pin-limited 6502) + TIA + RIOT (6532). The full common cartridge-scheme set is
implemented and was validated against the TOSEC 2600 library (2207 ROMs — all
load); the chief remaining accuracy gap is the HBLANK-aligned HMOVE model
(#406).

## What works

- **6507 CPU** — `mos-6502` running as the 6507 (13 address lines).
- **TIA** — pixel-level rendering for normal cart paths; A12/A7/A9 address
  decode; WSYNC halts the CPU until the next line start.
- **Frame-sync safety roll** (2026-06-17) — a game that never asserts VSYNC no
  longer runs the `vpos` line counter past the `u16` range (it previously
  overflowed/panicked after ~250 frames). The frame now rolls at 2× the region
  line count, mirroring a real display losing vertical sync; correctly-synced
  games reset via VSYNC well before the cap and are unaffected.
- **TIA read open bus** (2026-06-17, #415) — the TIA drives only D6/D7 on a
  register read; D0-D5 float and retain the last value on the data bus. Reads of
  collision/INPT registers now merge the retained low bits (matches Stella's
  `TIA::peek`), so kernels that test those bits read hardware-correct values.
- **RIOT (6532)** — timer + I/O; free-running prescaler (see disproven below).
- **Cart banking** — 2K/4K (none), F8 (8K), F6 (16K), F4 (32K) hotspot banking,
  plus Parker Brothers **E0** (8K, four 1KB slices; 2026-06-17, #411/#412) and
  CBS RAM+ **FA** (12K, three 4KB banks + 256 B on-cart RAM; 2026-06-17, #411). 8K
  is detected as E0 vs F8 by an instruction-signature scan; 12K is unique to FA.
  E0 fixed the Parker Bros titles, which previously hung before vertical sync —
  Frogger II now plays. FA's RAM uses a write port (`$1000-$10FF`) and read port
  (`$1100-$11FF`). **EF** (64K, sixteen 4KB banks, hotspots `$1FE0-$1FEF`;
  2026-06-17, #411) is also detected by its unique size. **UA** (8K, two 4KB banks;
  2026-06-17, #411) is signature-detected; unusually its bank-select hotspots
  sit *outside* the cart window (`$0220`→bank 0, `$0240`→bank 1), so the machine
  snoops every bus access and forwards it to the cart. The swapped-hotspot
  Digivision variant isn't modelled yet. **0840** "EconoBank" (8K, two 4KB
  banks; 2026-06-17, #411) uses the same snoop path (`$0800`→bank 0,
  `$0840`→bank 1) and is signature-detected (the signature must appear twice).
  **3E** (RAM+ROM; 2026-06-17, #411) maps a 2KB ROM segment *or* a 1KB RAM bank
  into the `$1000-$17FF` half-window — `STA $3F` selects the ROM segment, `STA
  $3E` the RAM bank — while `$1800-$1FFF` stays fixed to the last segment. It's
  size-agnostic and signature-detected; the value-carrying bank-select writes go
  through the same bus-snoop hook (extended to forward the written byte).
  **E7** (M-Network 16K + 2KB RAM; 2026-06-17, #411) maps a ROM bank or 1KB RAM
  into `$1000-$17FF` (`$1FE0-$1FE7`, `$1FE7`=RAM) with a 256-byte RAM strip at
  `$1800-$19FF` (`$1FE8-$1FEB`) and `$1A00-$1FFF` fixed to the last bank; each
  RAM region splits into a low write port and high read port. **3F**
  (Tigervision; 2026-06-17, #411) is the ROM-only sibling of 3E — a 2KB segment
  in the `$1000-$17FF` window selected by storing the bank to any `$00-$3F`
  address, `$1800-$1FFF` fixed to the last segment (detected after 3E, whose
  signature is a superset). The **Superchip (SARA) overlay** (2026-06-17, #411)
  adds 128 bytes of RAM (write port `$1000-$107F`, read port `$1080-$10FF`,
  present in every bank) over F8/F6/F4/EF when the repeated-padding signature is
  found — so F8SC/F6SC/F4SC/EFSC carts now carry their RAM. **FE** (Activision;
  2026-06-17, #411) has no conventional hotspots — an access to `$01FE` arms a
  probe and the next access's bus value picks the bank (`(value >> 5) ^ 7`), so
  the machine forwards every access (read and write, with the value) to the
  cart's `snoop_fe`. **DPC** (Pitfall II's coprocessor; 2026-06-17, #532) adds
  F8-style 8K program banking plus a 2K graphics ROM streamed through eight data
  fetchers (top/bottom comparators, 11-bit counters, flags), an LFSR, and
  register reads at `$1000-$103F` that mutate state. Graphics + RNG are
  CPU-read-driven; the three music-mode fetchers advance on a ~20 kHz oscillator
  timed against elapsed CPU cycles (the cart is ticked each CPU cycle, region
  clock rate set by the machine), feeding the amplitude reads the kernel writes
  to the TIA — so Pitfall II's 3-voice music plays.
- **Joystick** — validated at the register level: P0 in SWCHA high nibble, P1 in
  low nibble, active-low, per MAME `switch_A_r` (fixed this session, `fb44ad3a`).
  `vcs.input.swcha/swchb/inpt4/inpt5` queries added.
- **Fire buttons** (2026-06-17, #402) — wired end-to-end at last: a `fire`
  button event routes through `Atari2600::set_fire` to INPT4 (port 1) / INPT5
  (port 2). Previously the path dead-ended in the runtime, so no game's fire
  button worked. Keyboard-as-pad maps `fire` to player 1.
- **INPT4/INPT5 fire-button latch** (2026-06-17, #414) — VBLANK bit 6 enables
  latch mode: a press holds the line low until the bit is cleared (which
  re-opens the latch). With bit 6 clear the reads follow the pin. Per
  `reference/by-topic/tia/tia-reference.md` § Input.
- **RESx positioning delay** (2026-06-17, #405) — RESP0/RESP1/RESM0/RESM1/RESBL
  now land the object at the beam column plus a ~5-clock pipeline delay (TIA ref
  note 3), instead of exactly at the beam. Sprite columns shift right by 5 to
  match hardware. The finer HBLANK-region / active-HMOVE sub-cases remain
  approximate (saturating near the left edge).
- **Player NUSIZ** (2026-06-17, #408) — player copy layout and 2×/4× stretch are
  driven solely by NUSIZ bits 2:0; the player path no longer reads the missile
  size bits (5:4). Behaviour-preserving cleanup of dead/misleading code (double
  and quad already rendered via the size 0x05/0x07 paths).
- **Vertical delay (VDELP/VDELBL)** (2026-06-17, #407) — a GRPx write latches
  only the *other* player's delayed buffer (and the ball's, on GRP1), never the
  written player's own; ENABL no longer latches the ball's delayed enable (that
  happens on the GRP1 strobe). Matches Stella's shuffle model; the prior
  "delay-by-one-write" shape drifted under back-to-back GRP writes.
- **Audio** (2026-06-17, #403/#404) — both channels synthesised: the noise/pulse
  polynomial-counter model ported from Stella's `AudioChannel`, AUDC/AUDF/AUDV
  wired, two samples per scanline mixed through the non-linear volume table and
  drained each frame at the native ≈31.4 kHz (NTSC) / ≈31.2 kHz (PAL).

## Not implemented / accuracy gaps

- **TIA cycle-perfect timing** — HMOVE is HBLANK-aligned (no 8-clock beam
  injection / HMOVE-bar artefact, #406), plus RESP starfield edge cases. Bigger
  games (Pitfall, Adventure, Star Raiders) may surface issues. Gated by the
  frame oracle (#416) so the rewrite can be scored.
- **Starpath Supercharger (AR)** (#546) — ~50 TOSEC images are Supercharger
  loads (8448 B ×N); unsupported. It's a tape-loaded RAM peripheral, not a cart
  scheme — a separate subsystem.
- **Cartridge detection false positives** (#412) — the size-shared schemes are
  signature-detected (accurate for the specific-signature schemes); the fuzzy
  3F signature (`STA $3F` ×2) over-fires on a few carts (e.g. a 64K EF multicart,
  a Chopper Command overdump). A demand-gated CRC override is the fix.
- **Snapshot** — deferred (shared family pattern).
- **No native window.**

## Known unknowns / disproven hypotheses

- **DISPROVEN: "the joystick wiring is fine."** Players 0/1 were swapped between
  SWCHA nibbles; fixed against MAME `switch_A_r` (`fb44ad3a`).
- **DISPROVEN (donor): "reading INTIM resets the timer prescaler."** Real 6532
  silicon doesn't touch the prescaler on a read — the timer free-runs. Combat
  polls INTIM in a tight loop expecting the prescaler to keep decrementing; the
  donor's reset-on-read meant the wait loop never exited. Fixed: reading INTIM
  clears only the underflow flag.
- **Verification targets** — TIA HMOVE / RESP / audio-mixing behaviour against
  the Stella Programmer's Guide + reference emulators before treating the TIA as
  accurate.

## Validated against

- MAME `a2600.cpp` (`switch_A_r` joystick layout); Stella (reference).
- Combat (1977, 2K NTSC) boot smoke `tests/cart_boot.rs` (1/1).
- Cartridge detection vs the **TOSEC 2600 library** (2207 ROMs, 2026-06-18): all
  load via the zip/`.a26` path (#545); specific-signature schemes detect
  correctly against known carts (Pitfall II→DPC, Funky Fish→UA, Decathlon→FE,
  Bump 'n' Jump→E7, Parker Bros→E0, Crystal Castles/Dig Dug→Superchip). The 87
  `from_rom` rejections are Supercharger (#546) + bad/overdumped ROMs, not
  missing schemes.

## Timing & cycle-accuracy

- **Master clock & dividers** — the TIA colour clock is the master: 3.579545 MHz
  NTSC / 3.546894 MHz PAL. The 6507 and RIOT tick every **3rd** colour clock;
  TIA WSYNC halts the CPU until the next hblank.
- **Timing model realised** — among the more accurate donors: pixel-level TIA
  rendering, colour-clock-driven, with the genuine race-the-beam halting. The
  6507/RIOT 3:1 relationship is the real hardware ratio.
- **CPU timing** — 6507 cycle-accurate (§62; Tom Harte validates the 6502 ISA).
- **Distance to full cycle-accuracy** — TIA HMOVE quirks, RESP starfield edge
  cases, audio mixing; bigger games (Pitfall, Adventure) may surface gaps.

## Tooling & drivability

- **Script / MCP** — `--script` + `--mcp`; `vcs.input.*` query paths added this
  session.
- **TIA frame oracle** (2026-06-17, #416) — `atari-tia/tests/tia_oracle.rs`:
  deterministic register-driven scenarios (background, sprite positioning, HMOVE
  comb) rendered to a full frame and diffed pixel-exact against committed golden
  PNGs (`tests/goldens/`). A mismatch reports the differing-pixel count + first
  diff and dumps the actual frame to `target/tia-oracle/`. Re-bless intentional
  changes with `BLESS_TIA_GOLDENS=1` after verifying against Stella. This gates
  the cycle-accuracy work (the HMOVE rewrite in particular) as scored regressions
  rather than eyeballing.
- **Native window** (2026-06-18) — default mode via the shared `emu198x-ui`
  harness (wgpu video + raw/lcd/crt filters, framed TIA audio, keyboard/gamepad
  input, Esc-quit / F12-reset). Run `emu198x-atari-2600 <cart>`; automation
  flags (`--frames`/`--screenshot`/`--script`/`--mcp`) still select headless
  modes. The display shows the visible picture only — the 68-clock HBLANK
  margin and the VBLANK/overscan lines are cropped to Stella's visible window
  (NTSC 160×228, PAL 160×274) — and presented at a 4:3 display aspect (the
  harness derives the horizontal pixel-stretch from the cropped height), so the
  picture matches Stella's proportions pixel-for-pixel rather than looking too
  narrow.
  The 2600 is the first consumer of the harness; the other runners migrate onto
  it next. A halted 6507 (JAM/stop-code — usually a corrupted ROM
  dump) is surfaced as a full on-screen diagnostic overlay ("CPU halted (JAM)
  at $XXXX — likely a bad ROM dump", with a reset/quit hint), plus the window
  title, stderr, and the `cpu.halted` query — so a bad dump explains itself
  instead of showing a silent grey screen. The overlay is a generic
  `emu198x-ui` capability (any system can raise it via `UiSystem::halt_status`).
- **Disassembler** — pending the Asm198x shared 6502 disassembler.

## Peripherals & connectivity

- **Emulated now** — joystick (+ console switches, SWCHA/B queries), paddles
  (TIA INPT0-3 pot charge timing, `c2861c08`), **driving controller** (2026-06-17,
  #413) — Indy 500's quadrature wheel: a `cw`/`ccw` rotation event steps a
  two-bit gray code (`0x03,0x01,0x00,0x02`, per Stella `Driving.cxx`) onto the
  port's joystick up/down lines; fire reuses INPT4/5. One notch per event.
- **Keypad / keyboard controller** (2026-06-17, #413) — the CX-21/CX-23 4×3 key
  matrix: rows ride the four SWCHA output pins (the kernel scans one row low at
  a time), columns read on INPT0/INPT1 (analog) + INPT4 (digital) for the left
  jack, INPT2/INPT3/INPT5 for the right. A pressed key grounds its column only
  while its row is scanned, matching Stella's `Keyboard.cxx`. The machine bridges
  the RIOT row drive to TIA INPT levels each CPU cycle.
- **Booster grip** (2026-06-17, #413) — the CBS Booster-Grip is a joystick with
  two extra buttons wired to the jack's paddle INPT lines: the *booster* on
  INPT1 (left) / INPT3 (right) and the *trigger* on INPT0 / INPT2, each pulled
  to Vcc (reads high) when pressed (Stella `Booster.cxx`). Stick and main fire
  reuse the joystick paths. Host names `booster`/`boost` and
  `boostertrigger`/`trigger2` (the bare `trigger` stays the main-fire alias).
- **Genesis / Mega Drive pad** (2026-06-17, #413) — reads as a joystick with
  button B on INPT4/INPT5 plus a **C** button on INPT1 (left) / INPT3 (right),
  wired *inverted* vs the booster: pressed grounds the line (reads low), per
  Stella's `Genesis.cxx`. Host names `c`/`buttonc`/`cbutton`/`genesisc`. Button
  A isn't readable on a stock 2600.
- **Period peripherals (emulatable)** — light gun (Video Touch Pad / Kid Vid).
- **Internet-capable** — **Yes** (and delightfully so): the **CVC GameLine**
  (1983) was a cartridge *modem* that downloaded games over the phone line — a
  fully period, documented, emulatable net device. The 2600 was online in 1983.
