# Commodore 64

## Status: Fully playable — per-cycle VIC-II, reSID-grounded SID, real 1541 6502, disk + tape SAVE round-trip

The C64 boots the KERNAL, runs the commercial software library, and saves back to
disk and tape. The CPU is at the Tom Harte ceiling; the VIC-II renders per-cycle
with accurate badline / BA-stall / sprite-DMA timing; the SID is grounded in
reSID's tables; the 1541 runs its own internal 6502 against the real DOS ROM. The
distance to *true* 100% is concentrated in three places — the deepest VIC-II
raster tricks (VC/VCBASE-corruption effects), reSID-grade filter fidelity, and
preservation breadth (cartridges, extra drives, REU). None of those block a
learner shipping a game.

## What works

- **CPU (6510/6502):** all 151 official opcodes, the documented undocumented set
  (LAX, SAX, DCP, ISC, SLO, RLA, SRE, RRA, ANC, ALR, ARR, AXS), BCD with correct
  N/V/Z, the JMP-indirect page bug. **Tom Harte 100%** (single-step), Dormann
  functional, Lorenz suite. Per-cycle bus visibility drives VIC-II contention.
- **Video (VIC-II):** **per-cycle pixel pipeline** — `tick` advances one phi2 and
  renders 8 pixels. All display modes: standard/multicolour text, standard/
  multicolour bitmap, ECM. 8 sprites with multicolour, X/Y expansion, priority
  ($D01B), sprite-sprite ($D01E) and sprite-data ($D01F) collision with IRQ.
  Badline detection; badline DMA stalls the CPU across cycles 15–54 with the BA
  line leading `cpu_stalled` by three cycles (the NMOS 6510 AEC behaviour);
  sprite-DMA cycle stealing. XSCROLL/YSCROLL fine scroll, RSEL/CSEL 24/25-row +
  38/40-col, border flip-flops for border-opening, light pen ($D013/$D014),
  raster IRQs.
- **Audio (SID 6581):** 24-bit phase accumulator, 23-bit noise LFSR, four
  combinable waveforms (reSID combined-waveform ROM tables), ring mod, hard sync,
  test bit. ADSR rate-counter periods from reSID (`rate_counter_period[]`,
  cross-checked against VICE 3.10). 12 dB/oct state-variable filter (LP/BP/HP),
  per-voice routing. **The SID revision is model-selectable:** breadbin models
  fit the MOS 6581, the C64C models (`c64c-pal`/`c64c-ntsc`) the MOS 8580 (distinct
  combined-waveform and filter behaviour in `filter.rs`/`voice.rs`).
- **I/O (CIA 6526 ×2):** dual 16-bit timers (one-shot/continuous), TOD (BCD,
  latch-on-read, alarm IRQ), serial shift register (Timer-A clocked), 8×8 keyboard
  matrix, interrupt mask/ICR.
- **Storage — disk:** IEC serial bus driving a **real 1541** — the drive runs its
  own `M6502` against the 16 KB DOS ROM with a GCR surface. LOAD **and SAVE**
  round-trip: `SAVE"X",8` → `NEW` → `LOAD"X",8` → `RUN` reproduces the program
  (`disk_save_roundtrip.rs`). Mounts are writable on request; archive media stays
  write-protected by default (authentic `?WRITE PROTECT ERROR`). D64 parser with
  directory + sector-chain following.
- **Storage — tape:** datasette via the shared pulse timeline — TAP v0/v1, motor
  control ($01 bit 5), SENSE on CIA1 PB bit 4, edge → CIA1 FLAG. LOAD **and SAVE**
  round-trip: a writable blank tape records the KERNAL's write-line pulses ($01
  bit 3) and flushes to a `.tap` sidecar (`tape_save.rs` drives a real KERNAL
  `SAVE`). Archive tapes stay read-only; the writable work image is opt-in, the
  same write-back model as disk.
- **Files:** PRG (with BASIC-pointer fixup), BAS, **T64** container
  (multi-entry: first entry loaded, all entries enumerable), and **P00** (PC64)
  container (`file_loader.rs`).
- **Memory:** 64 KB RAM + BASIC/KERNAL/char ROMs, 6510 bank switching, colour RAM
  at $D800.
- **Input:** full PETSCII keyboard with shift-aware translation (RUN/STOP, CTRL,
  C=); **both control ports** (port 1 = CIA1 PB $DC01, port 2 = CIA1 PA $DC00);
  **paddles** share the port mapping. Host gamepad + host-key joystick.
- **Shell:** save/load state, tape play/stop, reset, rewind, cpal audio, native
  `wgpu` window (raw/lcd/crt).

## Not implemented / accuracy gaps

The C64 runs games well; the gaps are accuracy *depth* and preservation breadth,
not missing basics.

### Core accuracy

- **VIC-II video-matrix addressing is geometry-derived, not the hardware
  VC/VCBASE/RC counter chain.** Addresses are computed from raster geometry
  (`text_row = (raster_line − DISPLAY_START)/8`; the matrix row is fetched at
  cycle 15) rather than streamed through the real VC / VCBASE / RC counters. The
  per-cycle *timing* (badline, BA, sprite DMA) is accurate, so ordinary raster
  splits and register tricks work — but effects that **corrupt VCBASE/RC** to beat
  the hardware (VSP/AGSP, FLI, DMA-delay, the "linecrunch" family) are not
  guaranteed exact. This is the single biggest core-accuracy item.
- **CIA has no cycle-delay (write/IRQ) pipeline.** The 6526 applies timer and
  interrupt edges without the one-/two-cycle register-write and IRQ-delay
  pipeline of real silicon. Affects the tightest CIA-timed loops (the
  cycle-observable Lorenz `cputiming` / CIA-interaction cases).

### Audio fidelity

- **6581 filter below reSID grade.** The cutoff curve is a piecewise-linear
  approximation, not reSID's measured nonlinear response; the 6581's distortion
  and the filter's voltage-dependent behaviour are not fully reproduced.
- **$D418 volume-register digis** (4-bit sample playback) now play: the master
  volume scales an AC-coupled mixer DC bias, so writes to the volume nibble step
  the output even with silent voices. Only that volume-DC term is high-passed, so
  constant-volume voice output is byte-identical to before (existing captures
  unchanged). The reSID-exact digi amplitude and the DAC nonlinearity / DC offset
  remain Tier C work.
- **8580 filter below reSID grade.** The 8580 is now selectable via the C64C
  models, but its filter is a piecewise-linear approximation like the 6581's,
  not reSID's measured response, so 8580-tuned music is playable but not yet
  fidelity-verified.

### Preservation breadth

- **Cartridges** — `.crt` support covers plain 8K/16K + Ultimax (GAME/EXROM
  mapping) and the simple bank-switched types Ocean (5) and Magic Desk (19),
  which select 8K banks through a `$DE00` register. Still absent: the active /
  freezer carts (EasyFlash, Action Replay, Final Cartridge — their own register
  logic + flash banking) and the less common banked schemes.
- **Extra drives** — 1571 and 1581 (double-sided / 3.5″ 800K) absent; only the 1541.
- **RAM expansions** supported: **GeoRAM** (`--georam 512|1024|2048`; paged window
  at `$DE00`, block/page registers at `$DFFF`/`$DFFE`) and the **17xx REU**
  (`--reu 128|256|512`; DMA controller at `$DF00-$DF0A` with stash/fetch/swap/verify
  transfers, the `$FF00` trigger, autoload, and end-of-block IRQ). The REU DMA is
  modelled as a single atomic transfer, not cycle-stepped against the CPU/VIC.
- **1351 proportional mouse** supported (`--mouse-1351 1|2`): the POT lines
  report `(counter & 0x7f) + 0x40` deltas per VICE `mouse_1351.c`, and the two
  buttons ride the joystick digital lines (left → FIRE, right → UP). Host
  pointer motion and clicks drive it in the native window; the neos/smart/
  micromys variants are not modelled.
- **G64** (raw GCR) images and the heavier copy-protection schemes — D64 only.

### Validation debt

- **Software-autoload tests** gated on external archive paths sit `ignored`.
- **Lorenz** — the `cpu` subset passes; the cycle-observable timing cases
  (CIA interaction, tape KERNAL traps, IRQ-delivery edges, `cputiming`) are the
  documented skips and track the CIA-pipeline + VIC items above.

## Timing & cycle-accuracy

- **Clock chain** — PAL: 17.734472 MHz crystal; VIC-II dot = ÷4 (≈4.43 MHz);
  CPU = dot ÷8 ≈ 985 kHz. NTSC: 14.31818 MHz, CPU ≈1.0227 MHz.
- **Realised model** — per-cycle VIC-II (8 px/tick) with badline DMA stall
  (cycles 15–54), BA-leads-CPU-by-3, and sprite-DMA stealing, driven from a
  direct `cpu_stalled` flag (there is **no** `cpu_debt` abstraction — earlier docs
  named one that does not exist). One of the stronger cycle-accuracy stories in
  the fleet on *timing*; the gap is in VC/VCBASE/RC *addressing* fidelity, not the
  clock model.
- **Distance to full cycle-accuracy** — bounded and known: the VC/VCBASE/RC
  counter rewrite, the CIA delay pipeline, and second-SID/filter fidelity. The
  CPU instruction set is already exact.

  autoload walks the IEC + 1541 path end-to-end.

## Tooling & drivability

- **Script / MCP** — `--script` + `--mcp`; native interactive shell. Autoload:
  PRG/BAS/T64, TAP, D64 via the 1541/IEC path.
- **Native window** — yes: shared `wgpu` raw/lcd/crt, keyboard, audio, gamepad +
  host-key joystick.
- **Disassembler** — pending the Asm198x shared spec-driven 6502 disassembler.

## Peripherals & connectivity

- **Emulated now** — 1541 (D64 via IEC, real 6502, read+write), datasette (TAP),
  PRG/BAS/T64, both control ports + paddles + gamepad, 1351 proportional mouse,
  REU/GeoRAM, cartridges, light pen.
- **Period peripherals (emulatable, not yet built)** — 1571/1581 drives, MPS
  printers, user-port modems.
- **Internet-capable** — yes, historically: RS-232 user-port modems → BBS; modern
  kit (RR-Net/ETH64, WiModem232, Ultimate-II+ Ethernet) is a well-trodden path.
