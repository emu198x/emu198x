# Sinclair ZX81 - road to 100%

What it would take to bring the ZX81 to feature- and accuracy-complete, grounded
in a code-level survey of the four ZX81 crates and a live test run. Unlike the
C64/NES/Spectrum plans, this is a young, boot-tier system: the headline gap is
not a subtle counter rewrite but a deliberately stubbed "simplified v1" video
model that the code itself flags as not-yet-real.

## Executive summary

**The ZX81 is a fourth distinct shape: a boot-tier system whose long pole *is* its
defining feature.** The whole identity of the ZX81 - the thing that made it a
49.95 GBP machine - is that it has **no video hardware**: the display is generated by
the Z80 itself, bus-stolen one character-row at a time, with the ULA forcing
character-ROM bytes onto the data bus during the CPU's refresh cycles. The current
emulator **does not model that mechanism at all**. It runs the CPU, then at the
*end of each frame* walks the D_FILE structure out of RAM and paints glyphs into a
framebuffer (`crates/sinclair-zx81-ula/src/lib.rs:24-29`, `:130-134`,
`render_display` at `:220-308`). The source says so in its own words: *"It does not
model the bus-stealing display mechanism or the character ROM overlay on the data
bus"* and *"This is a simplified approach."*

That works well enough for the canonical SLOW-mode BASIC boot screen - the doc
status is "Boot screen renders" (`docs/status/current-system-usability.md:72`) -
but it makes the system a **screenshot of RAM, not an emulation of the machine.**
Anything that departs from the stock D_FILE layout - pseudo-hi-res (WRX),
non-standard character banks, scroll/raster effects, the entire ZX81 demo and
game scene that abuses the video generator - renders wrong or not at all. There is
no real per-cycle video, no real HSYNC/LINECNTR, no tape, no program loader, and a
snapshot that doesn't actually save machine state.

The good news mirrors the rest of the fleet: **the CPU is not the problem.** The
shared `zilog-z80` core is AT-CEILING (Tom Harte 1,604,000/1,604,000, FUSE
1351/1356 exact) and the ZX81 drives it correctly through the NMI/HALT path the
real machine uses. The ZX81's only latent CPU exposure is the IM0-collapsed-into-
IM1 gap - and the ZX81 uses IM1 + NMI, so that gap never fires here.

So "100% ZX81" is **a real ULA video rewrite + the missing I/O surfaces (tape,
program load, keyboard port bits) + a real snapshot**, not a counter-accuracy
finish on an otherwise-complete core. It is the *least finished* Sinclair system
in the fleet and the work is front-loaded onto one big item.

**Totals (focused work):**

| Tier | Scope | Estimate |
|------|-------|----------|
| A - "Curriculum 100%" | real bus-stolen ULA video (HSYNC/LINECNTR/character-ROM-on-bus), `.p`/`.p81` program loader, keyboard port bits (50/60Hz + EAR), real snapshot | **~5-8 weeks** |
| B - Display fidelity finish | pseudo-hi-res (WRX) + non-standard char-bank / CHR$128 modes, accurate vertical timing + border, FAST/SLOW distinction, NTSC (60 Hz) profile | **~3-4 weeks** |
| C - Tape + audio | cassette LOAD via `.p`/tape audio path + SAVE, the "buzz" audio the display generator produces on real hardware | **~2-3 weeks** |
| D - Preservation breadth | RAM-pack configs beyond 1K/16K, Timex TS1000/TS1500 variants, hi-res board variants (G007/QS), wobble/RAM-pack quirks, more program-image formats | **~3-5 weeks** |

**True 100% of everything ~= 13-20 weeks**, and it is **front-loaded** onto Tier A -
the opposite of the NES. The single dominant cost is the real ULA video rewrite;
once that exists, most of B and the preservation tail get *cheaper and provable*
because there is finally a per-cycle video pipeline to hang them on. The
launch-relevant slice (Tier A) is most of the value: a learner can already see a
boot screen, but cannot load or run a program, and anything graphically
interesting renders wrong.

Effort key: **S** = hours - **M** = a few days - **L** = 1-2 weeks - **XL** = multi-week.

## Tier A - Curriculum 100% (the front-loaded core)

| Item | Effort | Notes |
|------|--------|-------|
| **Real bus-stolen ULA video** | **XL** | Replace the end-of-frame D_FILE walk (`crates/sinclair-zx81-ula/src/lib.rs:220-308`) with the real mechanism: the ULA programs NMI per scanline, the NMI handler at `$0066` HALTs, and during the Z80 refresh cycle the ULA substitutes character-ROM data (driven by the I register high bits + the character code from the D_FILE byte fetched as an opcode) onto the data bus. This is what makes WRX hi-res, scroll tricks, and non-standard display layouts work. Today the per-cycle path is a fixed `nmi_active = in_display && line_tstate == 0` pulse at a hardcoded `FIRST_SCREEN_LINE = 56` (`:51`, `:117-122`) - geometry, not the real HSYNC/LINECNTR counter chain. The machine already feeds the ULA a `read_mem` closure each T-state (`crates/machine-sinclair-zx81/src/lib.rs:104-109`), so the seam exists; the addressing/timing underneath it does not. |
| **ULA oracle harness** | M | A per-frame (ideally per-scanline) comparator against EightyOne / ZEsarUX (both in `emulators/zx-spectrum/`) so the video rewrite is provable, not vibes. Build alongside Tier A, not after - there is no video test today beyond `nmi_during_display` (`:362-374`) and frame-timing asserts (`:321-333`). |
| **`.p` / `.p81` program loader** | **M** | No format crate exists (no `format-sinclair-zx81-*` under `crates/`), and `load_media` is a no-op (`crates/runtime-sinclair-zx81/src/runtime.rs:187-189`) despite a Tape media slot being declared (`crates/runtime-sinclair-zx81/src/profiles.rs:56-62`). The `.p`/`.p81` format is the de-facto ZX81 program image (a RAM dump from $4009). Without it a learner cannot load or run *any* program - only the BASIC boot prompt is reachable. Flagged outstanding at `docs/status/outstanding-work.md:768-769`. |
| **Keyboard port read bits (50/60 Hz + EAR)** | **S** | `io_read` returns the keyboard byte with bits 5-7 forced to 1 (`crates/sinclair-zx81-ula/src/lib.rs:212`, `(!result & 0x1F) | 0xE0`), and the odd-port path returns a flat `0xFF` (`crates/machine-sinclair-zx81/src/lib.rs:178-183`). Real ZX81 port reads carry bit 6 = the 50/60 Hz jumper and bit 7 = the cassette EAR line; ROM polls these during LOAD and vertical sync. Needs runtime verification of the exact bit assignment before wiring (see needs-runtime-verification). |
| **Real snapshot (save machine state)** | **S-M** | The snapshot serialises only version/time/model-id/ROM/RAM-*size* (`crates/runtime-sinclair-zx81/src/snapshot.rs:11-17`) - **not RAM contents, CPU registers, or ULA state.** `restore` therefore rebuilds a fresh machine (`rebuild_after_restore` -> `Zx81::new`), losing all program state. Rewind/save-state is silently a reset. Shared family deferral noted at `docs/status/outstanding-work.md:771`, but the on-disk snapshot is actively misleading, not absent. |

Tier A lifts the ZX81 from "shows a boot screen" to "loads and runs the library
with correct video" - the bulk of the "feels like a real ZX81" value.

## Tier B - Display fidelity finish (rides on the real ULA)

| Item | Effort | Notes |
|------|--------|-------|
| **Pseudo-hi-res (WRX) + non-standard char banks** | **L** | The WRX/hi-res technique repoints the I register so the refresh address indexes RAM as a bitmap, giving 256x192 monochrome. Impossible under the current D_FILE-walk model (`render_display` only reads glyph patterns from the first 512 bytes of ROM, `:270-278`); needs the real character-ROM-on-bus path from Tier A. Whole genres of ZX81 graphics depend on it. |
| **Accurate vertical timing, border, FAST/SLOW** | **M** | Today `FIRST_SCREEN_LINE` / `SCREEN_HEIGHT` / border are fixed constants (`:39-51`) and FAST vs SLOW mode is not distinguished on the ZX81 at all (the ZX80 plan notes FAST/SLOW as a known gap at `docs/status/outstanding-work.md:763-767`; the ZX81's NMI-driven SLOW path is the modelled one, FAST is not). Real vertical position is software-timed and varies; demos exploit it. |
| **NTSC / 60 Hz (Timex TS1000) profile** | **S-M** | The profile hardwires `Region::Pal` and 312 lines / 207 T-states (`crates/runtime-sinclair-zx81/src/profiles.rs:27-29`, `crates/sinclair-zx81-ula/src/lib.rs:44-47`). The US Timex TS1000 runs 60 Hz with a different line count. Add a region arg + profile, read the 50/60 Hz jumper bit through to the ULA. |

## Tier C - Tape + audio

| Item | Effort | Notes |
|------|--------|-------|
| **Cassette LOAD / SAVE** | **M** | Tape in/out is unwired: odd-port reads return `0xFF` with no EAR sampling (`crates/machine-sinclair-zx81/src/lib.rs:182`), and the `run_until` audio sink is fed an empty sample slice (`crates/runtime-sinclair-zx81/src/runtime.rs:228`). The Tape media slot is declared but inert. Add an EAR/MIC path; `.p` covers snapshot-style loading but real tape audio + SAVE is the preservation-faithful route. Flagged at `docs/status/outstanding-work.md:770`. |
| **Display-generator "buzz" audio** | **S-M** | The ZX81 has no sound chip, but the bus-stealing display produces a characteristic buzz on the tape-out line that some games used for crude sound. Only meaningful once the real ULA video path exists (depends on Tier A). The drivability survey lists ZX81 as a "near-silent machine" with non-empty captures (`docs/status/drivability-assessment.md:73`) - captures are non-empty only because the sink is fed silence. |

## Tier D - Preservation breadth

| Item | Effort | Notes |
|------|--------|-------|
| **RAM-pack configurations** | **S** | `Zx81::new` accepts any power-of-two RAM <= 16K (`crates/machine-sinclair-zx81/src/lib.rs:67-71`), but the runtime hardwires `DEFAULT_RAM_BYTES = 1024` (`crates/runtime-sinclair-zx81/src/runtime.rs:16`) and `set_ram_bytes` is never exposed as a command (`command` returns `UnsupportedOperation`, `:243-247`). Expose 1K/2K/4K/16K/32K/64K selection. The notorious 16K RAM-pack "wobble" crash is a Tier-D authenticity nicety, not a requirement. |
| **Timex TS1000 / TS1500 variants** | **S-M** | Only `Model::Zx81` exists (`crates/runtime-sinclair-zx81/src/profiles.rs:9-11`). TS1000 (US, 2K RAM, 60 Hz) and TS1500 (16K, different ROM) are close cousins sharing the ULA - add as profiles once NTSC + RAM-config land. |
| **Hi-res board variants (G007, QS, CHR$128)** | **M** | Hardware add-ons that altered the character-generation path for true hi-res. Niche preservation; rides entirely on the Tier-A/B video pipeline. |
| **More program-image formats** | **S** | Beyond `.p`/`.p81`: `.81`, `.o`/`.80` (ZX80), and any tape-container formats. Cheap once the `.p` loader establishes the RAM-image entry point. |

## Done as part of this plan (free, ~half a day)

System-doc / status touch-ups grounded in the code read. The status line
"Boot screen renders" (`docs/status/current-system-usability.md:72`) is accurate
but understates *why the ceiling is low*: it does not record that (a) the ULA is an
explicit "simplified v1" RAM-walk with no bus-stealing, (b) the snapshot saves no
machine state (RAM/CPU/ULA all dropped), (c) `load_media` is a no-op so no program
can be loaded, and (d) the Tape slot is declared but inert. The outstanding-work
section (`docs/status/outstanding-work.md:747-772`) already lists `.p` load, tape,
and snapshot as gaps but does **not** flag the simplified-ULA video model or the
state-less snapshot as the headline correctness items - correct those framings.
Test count: **16 passing unit tests** (9 machine + 6 ULA + 1 runtime) plus one
`#[ignore]` ROM-boot smoke test (`crates/machine-sinclair-zx81/tests/rom_boot.rs:22`,
needs an 8 KB ROM) - the outstanding-work "9/9 + 6/6" figures are per-crate and
correct as far as they go.

## Recommended sequence (highest leverage first)

1. **ULA oracle harness** (M) - build the EightyOne/ZEsarUX comparator *before* the
   rewrite, exactly as the C64 plan sequences the VIC-II oracle first.
2. **Real bus-stolen ULA video** (XL) - the single dominant item; everything in
   Tiers B/C/D gets cheaper and provable once it exists.
3. **`.p` / `.p81` program loader** (M) - the one Tier-A gap that stops *any*
   program running; highest non-video leverage. Can land in parallel with the ULA
   work since it is a RAM-image + entry-point concern.
4. **Real snapshot** (S-M) + **keyboard port bits** (S) - cheap correctness fixes;
   the snapshot one removes an actively-misleading "save state that resets."
5. **Pseudo-hi-res (WRX) + char banks** (L), then **vertical timing / FAST-SLOW /
   NTSC** (M + S-M) - the display-fidelity finish, all riding the real ULA.
6. **Cassette LOAD/SAVE** (M), then **buzz audio** (S-M) - the tape + audio surface.
7. **RAM-pack configs** (S), **TS1000/TS1500** (S-M), **hi-res boards + extra
   formats** (M + S) - the preservation tail.
