# Commodore 64 — road to 100%

What it would take to bring the C64 to feature- and accuracy-complete, grounded in
a code-level survey of the actual crates and tests (not doc prose — the system doc
had drifted in **both** directions and was corrected as part of this work).

## Executive summary

**The C64 is the opposite shape from the Spectrum.** The Spectrum's hard part was
done and the remaining work was breadth (storage write, clones, peripherals). The
C64 already runs the commercial library, saves to disk and tape, and has a real
1541 — so the *breadth* basics are in hand too. What's left is **depth**: the
dominant cost is a **VIC-II core-accuracy rewrite**, even though the machine plays
games fine without it.

That inversion is the headline. A learner can ship a C64 game today. "100%" means
the demoscene-grade raster tricks pass, the SID sounds reSID-identical, and the
preservation long tail (cartridges, extra drives, REU) is covered.

The CPU is already at the ceiling — Tom Harte 100%, Lorenz, Dormann — so unlike
most systems there is **no CPU work** on the road to 100%.

**Totals (focused work):**

| Tier | Scope | Estimate |
|------|-------|----------|
| A — "Curriculum 100%" | cartridges (so type-in *and* cart games run), 8580 selectable, $D418 digis, T64/P00 breadth, fastloader validation, doc fixes | **~4–6 weeks** |
| B — Cycle-exact core | VIC-II VC/VCBASE/RC rewrite (+ VIC oracle harness) and the CIA cycle-delay pipeline (+ full-machine Lorenz harness) | **~6–9 weeks** |
| C — reSID-quality audio | nonlinear 6581 filter, faithful 8580 filter, DAC nonlinearity + DC offset, filter-cutoff provenance | **~3–4 weeks** |
| D — Preservation breadth | active cartridges (EasyFlash/AR), 1571/1581, REU/GeoRAM, 1351 mouse, G64 + protections | **~5–7 weeks** |

**True 100% of everything ≈ 18–26 weeks.** Unlike the Spectrum it is **not**
front-loaded onto cheap wins — Tier B (the cycle-exact core) is the long pole and
is genuinely hard. The launch-relevant value (Tier A + the audible parts of C) is
a much smaller slice than the headline.

Effort key: **S** = hours · **M** = a few days · **L** = 1–2 weeks · **XL** = multi-week.

## Bucket 1 — VIC-II core accuracy (the long pole; L–XL)

| Item | Effort | Notes |
|------|--------|-------|
| **VC / VCBASE / RC counter rewrite** | **L–XL** | Replace geometry-derived addressing (`text_row = (raster_line − DISPLAY_START)/8`) with the real video-counter chain: VC latched from VCBASE, RC the row counter, advancing on badlines, with the c-access/g-access split streamed per cycle. This is what makes **VSP/AGSP, FLI, DMA-delay, linecrunch** exact. The per-cycle *timing* scaffold (badline, BA-by-3, sprite DMA) already exists and is correct — this is the addressing layer underneath it. |
| **VIC-II oracle harness** | M | A per-cycle comparator against VICE (or the VIC-II test ROMs / Lorenz VIC cases) so the rewrite is provable, not vibes. Build alongside, not after. |
| Sprite-DMA + sprite-pointer edge cases surfaced by the rewrite | S–M | Once VC/RC is real, re-verify sprite-Y-expansion crunch and the sprite-DMA-at-$D015-change cases. |

## Bucket 2 — CIA timing (L)

| Item | Effort | Notes |
|------|--------|-------|
| **CIA cycle-delay (write/IRQ) pipeline** | **L** | Add the 6526's one-/two-cycle register-write and IRQ-delay pipeline. Unblocks the cycle-observable Lorenz `cputiming` / CIA-interaction cases and the tightest CIA-timed effects. |
| **Full-machine Lorenz harness** | M | Wire the Lorenz suite at the *machine* level (it currently validates the bare 6502) so CIA + VIC + IRQ interaction is scored, not just the CPU core. Turns "15 skips" into a tracked, closeable list. |

## Bucket 3 — Audio fidelity (C; ~3–4 weeks)

| Item | Effort | Notes |
|------|--------|-------|
| **Nonlinear 6581 filter** | **L** | Replace the piecewise-linear cutoff with reSID's measured nonlinear response + the 6581 distortion model. The audible "this sounds like a real 6581" item. |
| **$D418 digis + DC offset + DAC nonlinearity** | M | 4-bit volume-register sample playback (whole genres of music) plus the DAC's nonlinear output. Currently silent. |
| **8580 wire-selectable on the C64** | S | The model already exists in the SID crate; expose it as a machine option (PAL/NTSC-style profile switch). |
| **Faithful 8580 filter** | L | Beyond wiring: the 8580's distinct (more linear, less distorted) filter to reSID grade. |
| **Filter-cutoff provenance** | S | Cite the measurement source behind the cutoff table in-repo, or replace with the reSID-derived curve as part of the nonlinear-filter work. |

## Bucket 4 — Preservation breadth (D; ~5–7 weeks)

| Item | Effort | Notes |
|------|--------|-------|
| **Cartridges — plain + banked** | M | `.crt` parser, plain 8K/16K + Ultimax (GAME/EXROM) mapping, simple bank-switched carts. **Tier-A priority** — without it, cart-only games don't run at all. |
| **Active cartridges** (EasyFlash, Action Replay, Final Cartridge) | L–XL | Freezer hardware + flash banking + their own register logic. The preservation long tail. |
| **Tape SAVE** | M | Datasette currently LOADs only; add the write path (motor-paced pulse emission + TAP writer + writable mount/flush), riding the C64 disk-save-write-back decision. |
| **1571 / 1581 drives** | L–XL | Double-sided / 3.5″ 800K with their own DOS ROMs + formats (D71/D81). Each is a drive-core in the 1541 mould. |
| **REU** | M | 17xx RAM Expansion Unit (DMA controller + RAM). |
| **GeoRAM** | S | Simpler banked RAM expansion. |
| **1351 proportional mouse** | M | POT-line proportional mode (paddles already share the port). |
| **G64 + heavier protections** | M/L | Raw-GCR images for copy-protected originals the D64 layer can't represent. |
| **P00 container** | S | Single-file PRG container; trivial parser. |
| **Fastloader validation** | S–M | Now the 1541 runs a real 6502, exercise a fastloader (Action Replay turbo, etc.) under test to confirm the GCR + IEC timing actually carries it. |

## Done as part of this plan (free, ~1 day)

Doc-drift eradicated in the system doc. The old doc was wrong in **both**
directions: it overstated the VIC-II (claimed a "VC/VCBASE/RC sequencer" and a
"cpu_debt model" — **neither exists**; the addressing is geometry-derived and the
stall is a direct `cpu_stalled` flag), and it understated the rest (disk SAVE
"in progress" — it round-trips; 1541 "doesn't run its internal 6502" — it does;
8580 "unmodelled" — it exists but is unwired; T64, port-1 joystick, paddles all
"nice to have / not done" — all wired; SID provenance "uncited" — reSID-cited
throughout). Test count corrected from a stale 73 to ~346 C64-specific.

## Recommended sequence (highest leverage first)

1. **Cartridges — plain + banked** (M) — the one Tier-A breadth gap that stops
   real games running at all. Highest leverage per week.
2. **8580 selectable + $D418 digis** (S + M) — the cheapest audible wins; whole
   swathes of music need digis.
3. **Fastloader validation + P00/T64 breadth** (S–M) — cheap confidence + format
   coverage now the real 1541 is in place.
4. **VIC-II oracle harness** (M) — build the comparator *before* the rewrite.
5. **VIC-II VC/VCBASE/RC rewrite** (L–XL) — the core-accuracy long pole; the
   demoscene-grade raster tricks.
6. **CIA cycle-delay pipeline + full-machine Lorenz harness** (L + M) — close the
   cycle-observable timing cases.
7. **Nonlinear 6581 filter** (L) then **faithful 8580 filter** (L) — reSID-grade
   audio.
8. **Tape SAVE** (M), then **REU/GeoRAM/1351** (M/S/M) — preservation mid-tail.
9. **Active cartridges** (L–XL), **1571/1581** (L–XL), **G64 + protections** (M/L)
   — the completionist long tail.
