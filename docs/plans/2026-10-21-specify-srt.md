# Proposed programmed step-rate implementation

Lane: **Spectrum launch-hardening**. Owning bug: [Emu#1970](https://github.com/emu198x/emu198x/issues/1970). Qualification consumers: umbrella#242 SPECIFY, #243 Seek and #241 Recalibrate. This document proposes a bounded design; it does not authorize a snapshot-format change or claim completed qualifications.

## Reproduced root cause

At `cacb63cfb78b080c681a5b1a436b4abb07447230`, Specify stores ND alone. Seek immediately changes PCN/physical position, then stages a fixed256-tick completion independent of SRT/distance. Recalibrate immediately zeros position/PCN, so it cannot search Track Zero or fail after77 pulses. See [the intentionally red diagnostic and receipts](2026-10-21-specify-srt/README.md): four cases twice, exact READY/SIS controls. No production code changes have been made.

## Recommended smallest implementation

1. Agree the digital step contract before editing runtime state. Bind it to the existing4MHz +3 controller and existing host T-state tick boundary, not a new clock API. Compare independently executed Fuse/MAME event traces for SRT0/1/E/F, zero/one/two-step and reverse journeys. Separate adjacent-step spacing (primary-defined) from first/final offsets (currently disputed by source precedent). Keep any unresolved edge as a named unresolved case.
2. In `crates/nec-upd765a/src/lib.rs`, retain one private programmed SRT nibble and replace instantaneous Seek/Recalibrate movement with per-logical-unit active motion. Use the existing four logical PCNs and masked physical heads, existing READY/T0 inputs and existing completion/SIS queues. A motion record needs kind (Seek/Recalibrate), latched physical drive and ST0 selector echo, target for Seek or remaining search pulses for Recalibrate, and fractional step phase. Direction derives from PCN/target for Seek; Recalibrate moves outward. Existing staged-ST0/countdown fields can be reused or replaced, with no redundant second completion queue.
3. Bind units to the current source: `SpectrumDriver::step_halfcycle` calls `on_tstate` once at the second CPU edge, independently of CPU contention; `common-sinclair-zx-spectrum-amstrad-class/src/core.rs::on_tstate` calls `fdc.tick(position.halfcycles())` exactly once per T-state. Its timestamp argument carries master-counter units, but `Upd765a::tick` currently ignores that argument. `timing.rs` defines the PAL crystal17734475Hz divided by5, hence3546895 ticks/second. One tick is about0.282us, not one4MHz FDC clock; the existing256-tick delay is about72.18us. Do not infer call duration from the misleading old~887kHz comment above `SEEK_TICKS`.
4. Derive paced events rationally from `(16−SRT)*2000us` and `CPU_HZ_128K`. Preserve fractional phase across steps so rounding each interval does not accumulate drift. Do not introduce a second machine clock or catch-up loop. Each due event changes physical position/PCN by at most one; subsequent events must use the accepted programmed timing contract. Decide and test whether SRT is latched per active journey or consulted at the next event when another SPECIFY arrives; existing command overlap makes this observable, so do not guess.
5. Recalibrate clears its logical PCN as specified, samples T0, then steps outward until T0 or77 pulses; on success retain zero PCN, on exhaustion report SE/EC/abnormal. Preserve initially-unready/mid-command READY failure semantics and independently queued logical completions. Physical position saturates only at an explicitly documented drive-model boundary, never because a mounted image has fewer tracks. Overlapping logical aliases share a physical mechanism; freeze event ordering and signal sampling before treating those cases as qualified.
6. Define reset/default programming explicitly. Power-on/reset SRT is not established by this packet. A model fallback may be documented but must not be called hardware-qualified; qualification always issues SPECIFY first. Reset aborts motion and cannot emit stale completion; mounted media and supplied external inputs follow the current reset contract.
7. Native state must retain programmed SRT, every active motion record, countdown/fractional phase, supplied inputs, position/PCN and pending/SIS progress. New private positional serde state changes Spectrum snapshots. **Approval for v10→v11, rejecting v10 before payload decode, is required before implementation.** A migration is possible but larger; serde defaults alone do not migrate positional Postcard. No new public chip input, script/MCP command or dependency is necessary for this bounded +3 implementation. Other controller clocks would require a separately approved interface.

## Verification and exact owning files

- `crates/nec-upd765a/src/lib.rs`: per-step implementation and existing unit tests that currently assert256 ticks; replace approximation assertions with independently derived invariants.
- `crates/nec-upd765a/tests/specify_step_rate.rs` (new after approval): SRT distinctness/boundaries, distance/reverse, READY/T0 before/during, concurrency and SIS/IRQ lifetime; assertions observe events rather than restating constants. Move the durable red diagnostic's invariant into this ordinary suite when the fix exists.
- Existing `seek_readiness.rs`, `logical_pcn.rs`, `sis_busy.rs`, `sis_interrupt.rs`, `recalibrate_not_ready.rs`, `ready_attention.rs`: preserve supported identities/queue behavior, update only assumptions disproven by the accepted motion model.
- `crates/runtime-sinclair-zx-spectrum/src/snapshot.rs` plus a focused included native test module: approved version handling and native checkpoints before/after step boundaries, pending/completed SIS, reset and independent unit motion. Source/live disks stay unchanged.
- Run targeted chip/native tests, Clippy and formatting, then relevant supported workspace build/tests once changes are complete. Require wrong expected spacing, missing prerequisites and altered trace negative controls to fail.

HUT/HLT, physical step-pulse widths, mechanical spin-up/settle, flux, arbitrary controller clocks and full operation qualification remain separate. This shared timing fix is useful without claiming any of umbrella#241–243 complete. If a required digital edge cannot be established from obtainable evidence, retain its blocker and advance another independently useful operation.


## Uncertainty stays separate

HUT/HLT zero encodings and head-load/unload transitions are not exercised or fixed here. Their manufacturer/reference discrepancies remain requirements of full SPECIFY qualification. Initial READY failure status has existing direct tests; exact READY loss sampling relative to a step edge, READY-attention interaction during concurrent motion, first-pulse timing and final completion offsets need an explicit independently checked case list before qualification. Excluding mechanical fidelity does not exclude those digital questions. No removal of them from the operation tickets is proposed.


## Implementation approved2026-10-22

The user explicitly approved Spectrum native snapshotsv10→v11 and this bounded fix. Implement the executed Fuse digital policy: immediate first step, adjacent programmed spacing, completion after the final interval, zero-distance completion immediate. These offsets are a documented model choice; MAME differs and silicon edge fidelity remains unqualified. READY is sampled initially and on each host tick during active motion. Reprogramming SRT changes newly scheduled intervals, not an interval already in progress. Recalibrate tests supplied/fallback T0 before a pulse and at paced boundaries, with77 pulses maximum. Reset aborts motion; default SRT0 is a model fallback, not an established hardware reset value. No new public interface/dependency is approved or needed.

Implement the source fix and focused direct/native regressions in one PR. Preserve source/live media and native continuation. Complete relevant chip/native tests, formatting, Clippy and supported Spectrum build. Avoid another campaign/reporting framework.


Reset retains the existing physical-head/logical-PCN preservation contract already exercised by `ready_inputs::controller_reset_preserves_logical_pcn_and_physical_position`; this fix does not introduce PCN reset semantics. The motion test captures both positions before reset and verifies no later pulse. Manufacturer reset PCN fidelity remains outside this bounded qualification claim. Supplied READY/T0 remain logical selector-slot samples as wired by the existing +3 adapter; physical head movement uses the latched masked destination.
