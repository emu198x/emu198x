# Synthetic Nintendo cartridges (boot evidence)

`nes.nes` and `game-boy.gb` are **synthetic, fully-free** cartridges
generated by [`build-synthetic-cart.py`](build-synthetic-cart.py). They
contain no code from any commercial game and exist so that "does this
machine boot" can be answered on every push, by anyone, with no ROM that
cannot be distributed.

Companion to [`../../sega/synthetic-cart/`](../../sega/synthetic-cart/) and
[`../../atari/synthetic-cart/`](../../atari/synthetic-cart/); see the Sega
README for why these seven machines can have this and the other
twenty-three cannot.

## NES

Points PPUADDR at `$3F00`, writes palette index `$30`, enables the
background, and spins. The PPU powers up with `$09` there, so a near-white
screen cannot be mistaken for an unrun machine.

**The two `bit $2002` loops are load-bearing.** A real PPU ignores writes
to PPUCTRL, PPUMASK, PPUSCROLL and PPUADDR for roughly 30,000 cycles after
reset, and this emulator models that. The first draft of the program wrote
its palette immediately, was silently ignored, and painted the power-on
colour — which is how the lock got noticed. Real cartridges wait two
vblanks before trusting the PPU, and so does this one.

## Game Boy

Turns the LCD off, sets `BGP` to `$FF` so every background index maps to
the darkest shade, turns the LCD back on, and spins. `BGP` powers up at
zero — every index to the lightest shade — so a machine that never ran the
cartridge stays light where this goes dark.

The palette is written with the LCD off because that is the only point the
hardware guarantees the write lands cleanly.

Its PPU emits indexed shades rather than colours, so the test asserts a
shade rather than an ARGB value. That is a per-chip choice, not an
inconsistency — see the framebuffer pixel-format decision.
