# Original A1200 v66 fixtures

Original engine: `cbcda19a116bdf3a86a8d41c186c046842c342b8`.
The first four boundary specimens were committed in `43931cd90` before extraction.
Four additional `-debug-cut` specimens were captured from a detached checkout
of the same original engine, using the public debugger until the scheduler
reported half-CCK phase 1. Every debugger cut also asserts that runtime time
and completed machine ticks agree. Original live and restored continuations
were compared before capture. The test is
`crates/runtime-commodore-amiga/tests/a1200_board_baseline.rs`.

The boundary specimens follow three native fields and a short `run_until`
request. The original runtime completes a field for that request; these are
boundary saves, not 137-tick cuts. The debugger specimens add an observed real
half-CCK cut. All four board/mode combinations exist at both cut kinds.

All firmware and floppy bytes are project-written synthetic input; no Kickstart,
Workbench or third-party software bytes are included. These prove continuation,
not historical-software qualification. The ROM assets are generated by
`build-firmware.py`, with byte identity checked against the original Rust
program generator. The script refuses to overwrite an existing file.

Each `.state` contains the entire original production v66 save, with held
keyboard/mouse/joystick controls and persisted synthetic DF0 media. Each
`.output` records three following native fields: elapsed clocks, SHA-256 of
each complete serialized frame packet, every audio packet's timestamp/rate/
channel count and f32 sample bits, and SHA-256 of the complete final save.
Controls release in the second following field; guest code reads the change.
A parked guest is the black/silent negative control. Capture is create-new-only
and refuses any source HEAD after the original base; never regenerate saves
or native observations using the extracted engine.

The immutable resampler kernel in `crates/emu198x-shell/data/` preserves the
original coefficient bits across hosts. All eight continuations compare
exactly on macOS ARM and Linux ARM, including pending f64 resampler history;
no platform-specific expected output or floating-point tolerance is used.
Linux x86 is also checked by the normal CI test job.
