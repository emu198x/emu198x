# Synthetic Atari cartridges (boot evidence)

`atari-2600.a26` and `atari-7800.a78` are **synthetic, fully-free**
cartridges generated by
[`build-synthetic-cart.py`](build-synthetic-cart.py). They contain no code
from any commercial game and exist so that "does this machine boot" can be
answered on every push, with no ROM that cannot be distributed.

Companion to [`../../sega/synthetic-cart/`](../../sega/synthetic-cart/) and
[`../../nintendo/synthetic-cart/`](../../nintendo/synthetic-cart/).

## Atari 2600

The odd one out. Every other machine here has a framebuffer its video chip
fills on its own; the 2600 has none. The TIA paints whatever its colour
registers hold as the beam sweeps, so the picture exists only because the
CPU and the beam run together. Writing `COLUBK` and spinning is therefore a
*complete* program — hardware paints every scanline after it.

It also means the picture is not uniform. The TIA renders the 68-clock
horizontal blank as black on every line, so the test crops to the visible
window rather than asserting over the whole buffer.

## Atari 7800

Writes MARIA's `BACKGRND` and spins. **No display list.** With DMA off —
the power-on state — MARIA fills every line with the background colour, so
that register alone is a complete picture. Driving a display list would
test the DMA engine, which is a different claim from "this machine starts".

MARIA shares the TIA's colour encoding and palette, so both machines paint
the same shade: value `$1C`, palette index `$0E`. The chips differ; the
claim being made about them does not.

## Regenerating

```sh
python3 test-data/atari/synthetic-cart/build-synthetic-cart.py
```

Deterministic; regenerating should produce no diff.
