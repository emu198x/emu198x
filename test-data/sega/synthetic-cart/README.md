# Synthetic Sega cartridges

`master-system.sms`, `game-gear.gg` and `sg-1000.sg` are **synthetic, fully-free** 32 KB
cartridges generated by
[`build-synthetic-cart.py`](build-synthetic-cart.py). They contain no code
from any commercial game and exist so that "does this machine boot" can be
answered on every push, by anyone, with no ROM that cannot be distributed.

## Why these machines can have this and most cannot

The Master System, Game Gear, SG-1000, NES, Game Boy, Atari 2600 and 7800
declare no firmware in their profiles: a cartridge is all they need to
run. Every other machine here needs its manufacturer's ROM to reach a
prompt, which is why 54 of this repository's 57 boot tests are gated
behind a fixture CI cannot hold.

That gap matters more than it looks. "It boots" is the most basic claim a
status page can make about a machine, and for most machines it is exactly
the claim that cannot be verified in public CI. Where a cartridge is
enough, it can — so it should be.

## What the cartridge proves

Deliberately the smallest program that cannot pass by accident. On reset
the Z80 fetches from `$0000`, and the program:

1. disables interrupts and sets the stack pointer,
2. writes a colour into CRAM through the data port `$BE`,
3. points the backdrop at it via VDP register 7,
4. enables the display via register 1 and selects mode 4 via register 0,
5. spins.

A test asserts the whole display holds that exact colour. CRAM powers up
as zeros, so the colour cannot appear unless the machine really executed
the cartridge: reset vector fetched, instructions run, I/O ports decoded,
VDP registers written, a frame emitted. A machine that hangs, never
fetches, or ignores its ports paints black instead.

`crates/machine-sega-master-system/tests/synthetic_cart_boot.rs` also
asserts that an **empty** cartridge fails that check, because an assertion
nobody has watched fail is not evidence of anything — see
[a gate nobody runs is a silent gate](../../../knowledge/decisions/a-gate-nobody-runs-is-a-silent-gate.md).

## Why three images rather than one

Each machine reaches its colour by a different route. The Master System's
palette is 6-bit in a single byte (`%00BBGGRR`); the Game Gear's is 12-bit
across two (`%GGGGRRRR`, then `%----BBBB`), from a different CRAM entry.
The SG-1000's TMS9918 has no colour memory at all — its backdrop is an
index into a palette fixed in silicon, taken from register 7. A single
shared image would exercise one path and imply the other two.

The images also confirm the display geometry the machines do not share:
280×240 for an NTSC television, 160×144 for the Game Gear's LCD (#1003).

280 rather than 288 because the width is what a set shows, and that is the
dot clock across an active line — 5.369318 MHz over 52.148 µs — not the
active area plus a border picked to be round. A PAL machine shows 277×288 on
the same reasoning. See
[`the-framebuffer-is-the-sets-window.md`](../../../knowledge/decisions/the-framebuffer-is-the-sets-window.md).

## Regenerating

```sh
python3 test-data/sega/synthetic-cart/build-synthetic-cart.py
```

The output is deterministic; regenerating should produce no diff. The
images are committed rather than built during the test run so that a
failure is a failure of the emulator, not of the toolchain that happened
to be on the machine — the same reasoning as
[the synthetic C64 KERNAL](../../commodore/c64/synthetic-kernal/README.md).

## `master-system-raster.sms` — timing evidence

The other three answer "did anything happen at all". This one answers
"when".

It arms the line-interrupt counter and has its handler change the backdrop,
so a frame comes out green above a line and red below it — and the position
of that edge *is* the interrupt's timing, drawn on the screen. The handler
tells a line interrupt from a frame one the way a game does, by reading the
status port and looking at bit 7, and re-arms the split every frame so it
stands in the same place on all of them.

What makes it evidence rather than a picture is that the edge's position can
be derived. From the counter underflowing to the backdrop changing, the Z80
spends up to twelve T-states finishing the `jr $` it was in, thirteen
accepting the interrupt, and fifty-eight running the handler as far as the
register write. Three dots to every two T-states turns that into a range of
screen positions, and `crates/machine-sega-master-system/tests/raster_split.rs`
checks the split falls in it.

The handler's cost is stated in the build script beside the instructions it
counts, so the two cannot drift apart silently — and `--check` in CI is what
stops the committed image drifting from either.
