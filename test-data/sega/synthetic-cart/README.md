# Synthetic Sega cartridges (boot evidence)

`master-system.sms` and `game-gear.gg` are **synthetic, fully-free** 32 KB
cartridges generated by
[`build-synthetic-cart.py`](build-synthetic-cart.py). They contain no code
from any commercial game and exist so that "does this machine boot" can be
answered on every push, by anyone, with no ROM that cannot be distributed.

## Why these machines can have this and most cannot

The Master System, Game Gear, SG-1000, NES, Game Boy, Atari 2600 and 7800
declare no firmware in their profiles: a cartridge is all they need to
run. Every other machine here needs its manufacturer's ROM to reach a
prompt, which is why 54 of this repository's 57 boot tests are gated
behind a fixture CI cannot hold.

That gap matters more than it looks. "It boots" is the most basic claim a
status page can make about a machine, and for most machines it is exactly
the claim that cannot be verified in public CI. Where a cartridge is
enough, it can — so it should be.

## What the cartridge proves

Deliberately the smallest program that cannot pass by accident. On reset
the Z80 fetches from `$0000`, and the program:

1. disables interrupts and sets the stack pointer,
2. writes a colour into CRAM through the data port `$BE`,
3. points the backdrop at it via VDP register 7,
4. enables the display via register 1 and selects mode 4 via register 0,
5. spins.

A test asserts the whole display holds that exact colour. CRAM powers up
as zeros, so the colour cannot appear unless the machine really executed
the cartridge: reset vector fetched, instructions run, I/O ports decoded,
VDP registers written, a frame emitted. A machine that hangs, never
fetches, or ignores its ports paints black instead.

`crates/machine-sega-master-system/tests/synthetic_cart_boot.rs` also
asserts that an **empty** cartridge fails that check, because an assertion
nobody has watched fail is not evidence of anything — see
[a gate nobody runs is a silent gate](../../../knowledge/decisions/a-gate-nobody-runs-is-a-silent-gate.md).

## Why two images rather than one

The two machines reach the same colour by different routes. The Master
System's palette is 6-bit in a single byte (`%00BBGGRR`); the Game Gear's
is 12-bit across two (`%GGGGRRRR`, then `%----BBBB`), and its sprite
palette starts at a different CRAM entry. A single shared image would
exercise one path and imply the other.

The images also confirm the display geometry the two machines do not
share: 288×240 for the television, 160×144 for the LCD (#1003).

## Regenerating

```sh
python3 test-data/sega/synthetic-cart/build-synthetic-cart.py
```

The output is deterministic; regenerating should produce no diff. The
images are committed rather than built during the test run so that a
failure is a failure of the emulator, not of the toolchain that happened
to be on the machine — the same reasoning as
[the synthetic C64 KERNAL](../../commodore/c64/synthetic-kernal/README.md).
